## 按需下载与离线覆盖

自 `0.2.0` 起，插件包不再携带五平台 CLIProxyAPI 核心，只保留固定版本清单、文档和许可证。`0.2.1` 将 MCP 握手与核心准备分离：**宿主启动插件 MCP 进程时会在后台自动准备核心**，无需先有模型、账号或工具调用；缺少有效缓存时通过系统 `curl` 和 HTTPS 下载当前平台的 `v8.0.38`，核验归档及二进制 SHA256 后缓存到 `dataDir/runtimes/v8.0.38/<platform-arch>/<basename(platforms.json.path)>`；默认 `dataDir` 为 `~/.zcode/zcode-subscription-proxy/data`。MCP 完成本地配置加载后即可握手，代理实际就绪由 `bridge_status.ready` 表示。`bridge_stop` 会取消本会话的在途准备并持久暂停，重连也不会自动下载或启动，需显式 `bridge_start` 恢复。没有账号不阻止管理页启动或握手。

自 `0.2.2` 起，后台核心准备保留独立的 **10 分钟（600 秒）**预算，超时或下载失败仍保留 MCP 连接，通过状态和安全 stderr 摘要报告原因；检查原因后可显式 `bridge_start` 或在宿主 MCP 设置中重连重试。本地配置不可用仍会导致初始化失败并非零退出。EOF、断管或退出信号会中止准备并清理。watchdog 不下载或自动重试下载；宿主何时自动连接 MCP 尚需官方证据，不承诺只打开空白 ZCode 就触发。核心下载不依赖扩大握手超时。

下载优先使用 `ZCODE_HTTP_PROXY`，否则沿用常见代理环境变量；不自动重试。10 分钟（600 秒）预算覆盖等待下载锁、下载、校验和解压，不代表 MCP 握手需要等待这些步骤。下载会连接官方发布托管服务及其重定向目标，可能经过你配置的代理；SHA256 校验能检验与固定清单的一致性，但不构成软件安全、来源数字签名或持续可用性的保证。离线 `BRIDGE_BIN` 覆盖的来源、兼容性与执行权限由用户确认，插件不会下载替代程序或更改该文件权限；实际启动仍会校验可执行性，失败不会被当作代理就绪。

当前源码移除大文件不会自动清除旧 Git 历史中的副本；本次不自动重写历史。
